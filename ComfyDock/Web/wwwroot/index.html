参数说明（每个选项是什么效果 / 什么时候该改）
提示词（默认空）——想画什么。自然语言（「一个女孩站在雨里，电影感，浅景深」）、标签串、或官方 Layout JSON（整段粘进来，宽高必须与 JSON 画布一致）。
写法：主体 + 动作 + 场景 + 光线 + 画风，越具体越可控；堆太多互相冲突的描述会打架，画面变糊或元素乱长。中英文都行（模型对中文手写文字也认）。
负向提示词（默认空）——不想出现的内容，如「多余的手指，文字，水印」。
官方推荐留空：MOSS 的默认口径下它收益很小；CFG = 1（8 步加速）时它完全不生效，填了也白填。
什么时候动：CFG ≥ 2 且反复出现同一类瑕疵时再填；填太多会把正常元素一起赶走。
方案（默认 int8）——用哪套权重，切换后要先把对应文件下齐（没下齐面板会红着说话）。
· int8：主模型 + 文本编码器都压 8 位，峰值显存约 8.7 G，10–18 G 显存首选；出图和 bf16 肉眼差别很小。
· bf16：主模型不压缩，峰值约 15 G，≥18 G 才建议；细节最完整，但更慢更吃显存。
· base：训练用的基础版；别配 8 步加速（配了出色块），只在训 LoRA / 要原始基座时用。
· diffusers：官方目录版（约 27 G），单文件格式出问题时的兜底，走 HF Loader，速度更慢。
· 8 步 LoRA：不是独立方案，任何方案都能加（见「8 步加速」）。
显存模式（默认「沿用引擎当前」）——这是引擎的启动参数，不是模型参数；改完必须到「环境与依赖」里点一次「按显存模式重启引擎」才生效（跑着的引擎不热改）。
· 沿用引擎当前：不动它，推荐。
· 按需放进显卡：默认行为，跑的时候整块显存都给它，最快。
· 逐层搬运：权重一层层搬进搬出，最省显存、最慢（显存明显不够时的救命档）。
· 全部常驻：整模型钉在显存里，≥30 G 才用，否则直接爆显存。
宽 / 高（默认 1024×1024）——成图尺寸，必须是 16 的倍数（面板自动对齐，填 1000 会变 992）。
显存与耗时随面积增长：面积翻倍约等于显存与时间翻倍。1024×1024 在 8 G 卡上 8 步约 30–60 秒；512 更快；2048 很慢且大概率爆显存。
宽高不必相等：1024×1536 出竖图、1536×1024 出横图。
粘 Layout JSON 时这里的宽高必须和 JSON 画布一致，否则构图错位。
步数（默认 50）——采样步数。
收益递减很明显：30 步以内提升快，40 步和 50 步几乎看不出差别，超过 50 基本是浪费。
开「8 步加速」就填 8（加速 LoRA 已把 50 步的行为蒸进 8 步）；开了加速却仍填 50 → 又慢又容易过曝。
关加速时填 4–8 会明显糊（模型没训过这么少的步数）。
CFG（默认 3）——提示词权重强度，决定「多听话」。
· 调高（5–8）：更贴提示词、对比更强，但容易僵、颜色过饱和发死、细节被压平。
· 调低（1–2）：更自由更柔和，但可能不听提示词、主体跑偏。
· 8 步加速时必须 1——蒸馏模型按 CFG 1 训，>1 会出色块 / 过曝，且此时负向提示词完全失效。
改 CFG 后建议先小图试。
Shift（默认 5，官方 MOSS 口径）——Flow 调度的时间步偏移，决定「前期定大形 / 后期抠细节」的步数怎么分。这是最不该乱动的一项。
· 调大（6–8）：更多步数花在定大形 → 构图更规整、对比更强、边缘更硬；过头会细节僵硬、暗部死黑、整体像被压扁、颜色发闷。
· 调小（3–4）：更多步数留给细节 → 画面更柔更细腻；过头则结构松散、主体不稳、容易糊成一团。
· 连带影响：Shift 同时是结构增强（SLG）的阈值基准（跳过第 22 层的判定与它共用），改 Shift 会一起改变 SLG 的实际效果——两者要调就一起调，别单动一个。
什么时候动：只在「整体明暗 / 结构倾向明显不对，且已排除提示词与 CFG」时小步试，每次 ±0.5，一次只改一个参数。
种子（默认 -1 = 随机）——随机数起点。
· 留空或 -1：每次生成都不一样。
· 填固定数字：同参数 + 同种子 = 同一张图，用来复现或微调（只改一个参数看变化）。注意任何参数 / 方案 / 模型变了，同种子也会出不同的图。
产物文件名就是种子——看到喜欢的图，记下文件名即可复现。
批次（默认 1）——一次出几张图，显存与耗时按张数线性增长（8 G 卡建议 1–2）。
它是同一次采样出多张，不是多跑几轮；要「同提示词不同种子」请改种子重跑。
LoRA / 权重（默认不用 / 1.0）——挂你自己的风格或角色 LoRA。
权重 0 = 不生效；1 = 作者标注的原强度；0.5–0.8 更轻、更像原生；1.5–2 更浓，过头会糊、色彩崩坏、画面出格子或重影。
内置的 8 步加速 LoRA 是另一条通道（由「8 步加速」开关控制），不受这里影响，两者可叠加。
8 步加速（DMD）（默认关）——挂蒸馏 LoRA，把 50 步的行为压到 8 步，速度快约 4–6 倍。
开了必须配套：步数 8、CFG 1（否则出色块 / 过曝），此时负向提示词失效。
只配 SFT（含 int8 压缩版）；配 base 会出色块。
质量代价：密集小字、细密纹理这类极端细节略弱于 50 步官方口径；日常出图看不出差别。
结构增强（SLG）（默认开）——负向分支跳过第 22 层（0 起算），让结构和手更稳，官方推荐开。
· 关掉：更快（省掉一路计算），但手 / 肢体 / 结构崩坏概率上升。
· 换层数（如 18 / 26）：等于换「在哪一层做引导」；越靠后越只影响细节，越靠前越影响大形。一般不需要动。
· 与 Shift 共用阈值基准，改 Shift 会连带改变它的实际效果。
Hires 第二遍（默认关）——先出小图，再像素放大（Lanczos）后以较低重绘幅度采样一遍，用来加细节、去小图噪点。
为什么必须走像素放大：MOSS 的 latent 是 128 通道（Flux.2 格式），不能像普通 4 通道 latent 那样直接插值放大。
· 倍率（默认 1.5）：1.5 = 边长 ×1.5（1024 → 1536）；越大越清晰也越慢越吃显存（面积按平方涨）。
· 重绘（默认 0.5）：0.5 = 改一半；0.3 更接近原图但细节加得少；0.8 变化大但容易跑偏（人物走形）。
代价：总耗时 ≈ 第一遍 + 第二遍，8 G 卡上 1024×1024 开 Hires 要按分钟算。

参数说明（每个选项是什么效果 / 什么时候该改）
这是在干什么——Irodori-TTS 是日语 TTS（RF-DiT + DACVAE 连续隐变量，48 kHz 单声道输出）。三类条件各管一段：文本决定说什么、参考音频决定谁在说（零样本音色克隆）、风格描述决定怎么说。角色 LoRA 再把这套基座往某个具体音色上偏一点。
跑法（默认 small）——一次定死「用哪个基座 + 哪个 LoRA + 精度 + 声码器放哪」，不是四个独立开关。三档都是依田芳乃这一套 LoRA（small 线 rank16 / large 线 rank32），区别只在基座大小。
· 依田芳乃 · v4.1-Small · 全 GPU：500M，显存约 4~5 G，首句加载约 19 秒、单句 13~20 秒，日常首选。
· 依田芳乃 · v4-Large int8 · 全 GPU：3.29B 压成 int8（3.58 G 权重），8 G 卡实测可用——首句 48~53 秒、单句 30~38 秒，峰值显存约 7.7 G。质量更好，代价是慢一倍多。
· 依田芳乃 · v4-Large bf16 · 声码器在 CPU：12.25 G 权重按 bf16 上卡约 6.6 G；8 G 卡实测会在采样阶段把显存吃到 7859/8188 MiB，单句两分钟出不来——只有显存富余时再用。
· 依田芳乃 · v4-Large bf16 · 全 GPU：≥12 G 显存才选，解码最快。
· 自定义：用「环境与依赖」页里填的路径与声码器设备，换别的角色 / 别的权重 / 做实验时用。
切跑法会立即落盘并重启常驻引擎（引擎按「基座 + LoRA + 精度 + 声码器设备」判断要不要重载），所以切一次要等一次加载。
依赖从哪来——这一路不再单独装运行时：直接用本机 ComfyUI 的 python_embeded（torch / torchaudio / transformers / peft / dacvae / silentcipher 都在里面，torchao 已补装）。权重与代码也都放在 ComfyUI 目录下：代码在 ComfyUI\irodori-tts\，权重在 ComfyUI\models\TTS\yoshino\。以后重装 / 升级 ComfyUI 时，缺 torchao 就补一条 pip install torchao==0.16.0（仅 int8 跑法需要）。
文本（必填）——要读的日语内容。标点保留（模型按标点断句、按时长预测估总长）；一行一句最稳。假名 / 汉字混写都行，读法由模型自己判——生僻人名地名容易读错，写成假名可以强制读音。
风格描述（默认空，自由文本不是选项）——模型这一路是 caption 条件（训练时喂的是自然语言描述），所以它吃的是「怎么写」而不是「选哪个」，这也是它没有下拉框的原因。框下面那排是常用写法模板，点一下填进框里，可以再改、可以拼两三条。
· 留空：完全靠参考音频的音色 + 参考音频自带的语气。
· 写什么会影响什么：嗓音质地（高い / 低い / 柔らかい / ハスキー）、语速节奏（ゆったり / 早口 / 間を取る）、情绪（明るく / 落ち着いた / 照れながら）、距离感（近い距離感 / 電話越し / 囁く）。
· 写法：一条 1~2 句就够，越具体越可控；堆太多互相打架的描述（既「囁き」又「元気いっぱい」）会两头不靠。
· 和参考音频冲突时：音色（谁）由参考音频主导，语气（怎么说）由风格描述主导——要换音色改参考音频，要换语气改这里。
步数（默认 40）——采样步数，官方口径 40。
降到 6~10 用 Sway 采样能快，但质量明显下降（这条链路没开 Sway，降步数就是纯掉质量）。超过 40 收益极小，只烧时间。
种子（默认 -1 = 随机）——固定数字 + 同样参数 = 同样的音频（实测 int8 档复跑 SHA-256 完全一致）。挑到喜欢的一条，记下种子就能复现；只改一个参数对比效果时尤其有用。
时长倍率（默认 1.0）——v4 系列会自己预测输出长度，这个数是在预测结果上再乘一遍：1.1 = 慢 10%（更从容），0.9 = 紧 10%。整体语速偏快偏慢时微调它，别当成「精确时长」用。
强制秒数（默认空 = 自动）——填了就直接盖掉时长预测，按这个秒数生成。只在「必须卡进某个时长」时用：填得比文本需要的短会把话压扁甚至吞字，填长了尾巴拖静音。
精度（默认 bf16）——bf16 更快更省显存，8 G 卡必选；fp32 数值最稳但显存翻倍，一般只在排查数值异常时试。int8 跑法下这一项被忽略（权重已经是 int8，精度固定 bf16）。
挂 LoRA（默认开）——走当前跑法对应的角色 LoRA（small 线 = rank16 500 步，large 线 = rank32 400 步）。关掉 = 只用基座的通用音色，用来对比「LoRA 到底改了多少」。跑法与 LoRA 必须配对（small↔small、large↔large），错配会加载失败。
参考音频（默认全选）——零样本音色克隆的输入：参考音频是「谁」，文本是「说什么」。
· 多选按勾选顺序拼接，30 秒左右收益最大（训练时就是这么拼的）；只给一段也能用，但相似度略低。
· 一段都不勾 = 用目录里全部。
· 质量要点：干净、单一说话人、无音乐无噪声；参考里的语气会顺带被学走（想换语气用风格描述压）。
· 不要用「不用参考音频」除非就是要听基座通用音色——那时音色会漂，风格描述也能单独生效。
停止引擎——常驻引擎会一直占着显存（small 约 4~5 G，int8 大模型约 7.7 G）。要跑 ComfyUI 出图、或者今天不打算再合成，点它把显存还回去；下次「生成」会自动重新加载（small 约 20 秒、int8 约 50 秒）。

这是在干什么——把图片反推成 Danbooru 标签：分级（general / sensitive / questionable / explicit）、角色名、以及一堆通用描述标签（1girl / long_hair / blue_eyes…）。产出的标签串可以直接粘进文生图的提示词框。
输入——给一张图就打一张；给目录就把目录里（一层）所有图片挨个打一遍。结果里每张图都带缩略图与命中标签；勾了「落 txt」会额外在图片同目录写一份同名 .txt。
模型——固定 EVA02-Large（数据集 v3，0.3B 参数，标签截至 2024-02-28），索引里只有这一套。模型存在 ComfyUI 的 models\onnx\wd-tagger\eva02-large\ 下，软件不打包权重；不在位时到「环境与模型」页一键下载。
通用阈值（默认 0.35，官方口径）——通用标签的入选线。
调高（0.5+）：只留很有把握的标签，串更短更干净；调低（0.2）：标签更多更全，但会混进噪声（模型瞎编的细节）。
建议先 0.35 看一遍，嫌少往 0.3 走、嫌多往 0.45 走。
角色阈值（默认 0.85，官方口径）——角色名的入选线，故意定得很高：角色词表有几十万个名字，阈值低了几乎每张图都能「认」出几个角色。
调低（0.6~0.7）：更容易认出冷门角色，误认概率同步上升。一般不用动。
MCut（默认关）——不用固定阈值，改成按「本图概率分布的最大间隔」自己切一刀。好处是每张图都能自适应（该多的多、该少的少）；坏处是不可复现、跨图结果不可比。
批量整理素材时建议开；要严格可对照时关掉用固定阈值。角色组开 MCut 会自动加下限 0.15。
设备（默认 auto）——auto 有 CUDA 就走 GPU；CPU 也能跑，ComfyUI 正在出图时用 CPU 可以避免抢显存。
落 txt（默认开）——在图片同目录写一份同名 .txt，三行：rating / general / characters。不想污染原目录就关掉，结果仍在面板里。

参数说明（每个选项是什么效果 / 什么时候该改）
这是在干什么——RVC 把一段人声的「音色」换成另一个音色，内容（说了什么、什么语调）保留。链路是：HuBERT 提内容特征 → 用检索索引往目标音色上拉 → 提取基频 F0 → 生成器按 F0 与内容特征重新合成波形。
模型住哪——音色模型（.pth）与检索索引（.index）都在本机 ComfyUI 的 models\RVC\ 下，特征提取器（HuBERT）与基频提取器（RMVPE）也在那儿。软件本体只带推理代码与面板，不打包权重。
音色——选一个 .pth。名字对得上的 .index 会自动挂上（面板会显示「索引：xxx」）；没索引也能跑，只是没那么贴训练音色。
F0 取法（默认 rmvpe）——决定「音高曲线怎么测」。
· rmvpe：神经网提取，音准与鲁棒性最好，显存多占一点，默认就用它。
· pm：Parselmouth（Praat）自相关，最快，但噪声与气声段容易测错。
· harvest：pyworld，最稳最慢，适合干净清唱素材。
· crepe：神经网 + 中值滤波，介于其间。
音高测错会直接表现成跑调或电音——先换 rmvpe 试。
变调（默认 0）——把整段音高平移 N 个半音：男声转女声约 +12，女声转男声约 -12；同性别之间通常 ±0~2 微调即可。只改变调，不改变语速（时长由内容特征决定）。
说话人（默认 0）——模型内部的音色编号，多数单人模型只有 0；多人模型（如 109 人那种）才需要切。
检索混合（默认 0.75）——把目标音色训练时留下的特征按这个比例混进输入特征。高（0.8~1.0）更像训练音色但咬字更糊；低（0.3~0.5）咬字清楚但音色没那么贴；0 = 完全不挂索引（用索引文件里那条链跑，速度快一点）。没有索引文件时这一项自动失效。
保护（默认 0.33）——清辅音保护：气声、齿音这类「没有明确音高」的段落按比例保留原声特征，防止被合成器吃掉。越小保护越强（0.2 更保气声，但可能带出原音色的杂音）；0.5 = 关闭保护。
响度混合（默认 0.25）——输出波形的响度曲线按这个比例混回输入的响度。0 = 完全用输出自己的响度（更平）；1 = 完全跟输入（原音频的强弱起伏保留）。听着「忽大忽小」就调低，听着「太平没起伏」就调高。
滤波半径（默认 3）——只有 harvest 取法用得到，做中值滤波平滑音高曲线；其余取法忽略这一项。
输出采样率（默认模型自带）——模型训练时的采样率（32k / 40k / 48k）就是它的原生输出，改成别的值会做一次重采样，除了「必须喂给某个只吃 44.1k 的软件」之外没有好处。
半精度（默认开）——fp16 推理，省显存、略快；CPU 上自动关闭（CPU 跑半精度反而慢）。
停止引擎——常驻引擎会一直占着显存（HuBERT + 一个音色模型）。要跑 ComfyUI 出图、或者今天不打算再变声，点它把显存还回去；下次「开始变声」会自动重新加载（约 5~15 秒）。

参数说明（每个选项是什么效果 / 什么时候该改）
这是在干什么——Qwen3-Omni-30B-A3B（GGUF Q4_K_M）经 llama.cpp 把一段音频整条转成文字。音频入口在 mmproj（AuT 音频编码器），主模型压 Q4 不影响音频编码质量。不切片、不开 ComfyUI 服务、不开端口。
模型与引擎住哪——主模型与 mmproj 在 ComfyUI 的 models\LLM（合计约 20.8 G），引擎 llama-mtmd-cli.exe 在 ComfyUI\tools\llama-omni\bin——都随 ComfyUI 走，软件本体不打包、不复制。
输入——音频或视频，也可以给一个目录（只取一层，音频与视频都收）。视频会先抽成 16 kHz 单声道 wav 再送模型（PyAV 解码），临时 wav 跑完即删，原始视频不动；视频没有音轨直接报错，不静默跳过。
提示词（默认不用改）——默认就是「按时间 + 内容的逐字稿」：每行 [mm:ss]内容，按实际说话顺序、不合并不概括。要加说话人、要纯正文、要整段不分行，才需要展开改它。
上下文（默认 65536）——模型原生上限，音频 token（约 13.05 个/音频秒）与输出 token 共用它。单次输入上限 5000 秒（约 83 分钟）；改小会让长音频的转写被截断，一般不动。
生成上限（默认 0 = 自动）——自动口径 = min(6.5 × 音频秒 + 512, 上下文 − 13.05 × 音频秒 − 456)。给少了转写会被静默截断（尾巴丢掉）；只有想限制输出长度或做对比实验时才手填。
NCMOE（默认 48）——把前 N 层 MoE 专家权重留在 CPU：30B 装进 8 G 显存的标准打法。显存越大可以调小（更快），调到 0 = 全放显存（≥ 24 G 才够）；显存不够会直接 OOM。
落 txt（默认开）——每条结果写 out\omni\<媒体名>.txt，内容是引擎输出原样。关掉就只在面板里看，不碰磁盘。
时间列是模型推的——不是真实时间戳：段内时间可能溢出段长，长段会被并成一行。内容列偶有人名 / 机构名幻觉，关键字段建议与来源核对。
退化截断——连续同句重复超过 5 次判为退化：保留前 5 行 + 一行标注，其后丢弃。看到这行标注说明这一段模型跑飞了，换提示词或切片重跑。
停止——结束在跑的引擎进程（这一条作废，显存还回去）。引擎每条都重新加载模型（约 30~60 秒），所以批量跑比单条更划算。
